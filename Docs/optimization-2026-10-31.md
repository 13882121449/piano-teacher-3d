## 2. 三个「实现完成但默认关闭」的决定

这三项都不是「没做」，而是**做了、量了、按数据关掉**，参数与实现全部保留。

### 2.1 腕高自适应（接触方案 2.4）→ `WristHeightAdaptation = false`

| 口径 | 效果 |
|---|---|
| 均值反馈（首版） | 键面 P95 三曲变化 +1.9 / +0.2 / −0.5 mm；压键帧 −3 / −3 / 0 |
| 极值+中位数（改进版） | 压键帧与首版差 −1/+5/+5（噪声内）；悬空帧 −7/0/0 |

根因：一手 5 指若 3 指悬空 20 mm + 2 指压入 8 mm，均值只有 +8.8 mm，落在死区（−6~+15 mm）。
限幅 ±8 mm 与问题量级（键面 P95 17–46 mm、压键数百帧）不匹配——**根因是手指弯曲不足**。

### 2.2 黑键目标抬升 → `BlackKeyTargetLift = 0`

抬 3 mm 让键面 P50 9.1 → 11.0 mm（指尖整体上移，反而更远），压键帧仅 110 → 107。
说明该曲压键的平均压入量远大于 3 mm，抬目标救不回来。

### 2.3 2.3 可达性判定的实测结论

原 (c) 类归因用键盘包围盒判定，按压点恒在盒内 → 触发恒为 0（死代码）。
改为肩距判定（含手长，`(上臂+前臂+掌长+中指) × BodyScale × 0.98`）后仍为 0——
与几何估算一致（端点按压点距肩约 0.53 m，可及半径约 0.55 m）。**当前内容没有不可达样本**。

顺带定论：换位峰值 250 mm 不是可达性问题，而是物理约束——
0.125 s（16 分音符 @120BPM）× 60 fps × 35 mm/帧 = 262 mm，正好等于峰值。
要压到 ≤100 mm 需把 `MaxStepPerFrame` 提到 ~75 mm/帧（4.5 m/s），属产品决策，未擅自改动。

## 3. 关键工程决策

### 3.1 静止手型与 CCD 初值解耦

`RestCurlDegrees` 26 → 70（MCP 25 / PIP 30 / DIP 15）。它同时是 CCD 初值，
直接改会改变收敛路径、让接触指标漂移。故新增 `SolveSeedCurlDegrees = 26`：
**观感改进走静止手型，指尖求解保持既有基线**。

### 3.2 立体声展开用声像而不是双声道波形

双声道合成让每个音高常驻内存翻倍（0.44 → 0.88 MB，极端 88 键 77 MB）。
改由播放端 `AudioSource.panStereo` 按音高分配（±0.30），听感上同样是左右分布，零额外内存。

### 3.3 URP 点光是物理单位

同样的 `Light.intensity` 在 URP 下比内置管线亮得多——实拍把琴体上半板打成黄斑、
地面过曝。加 `UrpPointLightScale = 0.42`，并让 `ApplyQuality` 重写强度时使用缩放后的值
（否则每档都被覆盖回原值）。

### 3.4 曝光三轮迭代（每轮 `--visual` 约 6 分钟，实拍判定）

| 轮次 | 观察 | 调整 |
|---|---|---|
| 1 | 地面过曝发黄、琴体上半板黄斑 | 点光 ×0.42、琴漆 0.55→0.40、Bloom 0.35→0.22 / 阈值 1.1→1.3 |
| 2 | 黄斑消失但整体欠曝（地面/背景近黑） | Trilight 三色提亮、地面反照率 0.105→0.135、背景板 0.125→0.150 |
| 3 | 曝光平衡：地面可见、琴体为深胡桃木、无过曝 | 定稿并重采 20 张基线 |

## 4. 未做项与理由

| 项 | 理由 |
|---|---|
| 程序化贴图（胡桃木纹 / 象牙微纹理 / 红绒） | 程序化网格共享顶点（顶点预算 ≤64），无 UV；贴图需拆顶点（破坏倒角柔性高光）或三平面着色器。改由反射探针 + 琴漆光泽承担写实感 |
| 手键接触门禁断言化（键面 P95 ≤15 / 悬空 ≤3 / 压键 =0） | 当前三曲均未达标，写入即红。已记录差距与归属（手指弯曲链路），待弯曲改进后一次性收紧 |
| `MaxStepPerFrame` 提高以压换位峰值 | 4.5 m/s 的手速是否可接受属产品决策，需先有 `--visual` 动态评估 |
| Rocketbox body/opacity 主贴图 | 资产本机不可得（GitHub/huggingface 不可达），资产门禁继续拒绝并回落内置角色 |
| 特写躯干入画 | 键位不被头部遮挡的断言已通过；躯干只占画面边缘，与「看得见琴键」的构图要求冲突，属可接受折中 |
| 音色主观评价 | `-nographics` 无法验证听感，需真机试听 |

## 5. 复现方式

```bash
# 全量（编译 + EditMode + PlayMode）
python Tools/verify.py --timeout 900

# 追加压力与性能
python Tools/verify.py --stress --perf --timeout 900

# 视觉基线（需真 GPU，会弹 Unity 窗口）
python Tools/verify.py --visual --timeout 900

# 手部指标（bench 三曲，含分组门禁）
Unity -batchmode -nographics -runTests -testPlatform PlayMode -testFilter HandBenchmark \
  -testResults _verify_out/bench.xml
```

**环境前提**：本机须把 Unity 安装目录与项目目录加入 Defender 排除项，否则 URP 相关
batchmode 会在 Bee/ILPP 的命名管道 IPC 阶段挂死（实测五次卡死，加排除项后 32 s 跑完）。
