## 2. 三个「实现完成但默认关闭」的决定

这三项都不是「没做」，而是**做了、量了、按数据关掉**，参数与实现全部保留。

### 2.1 腕高自适应（接触方案 2.4）→ `WristHeightAdaptation = false`

| 口径 | 效果 |
|---|---|
| 均值反馈（首版） | 键面 P95 三曲变化 +1.9 / +0.2 / −0.5 mm；压键帧 −3 / −3 / 0 |
| 极值+中位数（改进版） | 压键帧与首版差 −1/+5/+5（噪声内）；悬空帧 −7/0/0 |

根因：一手 5 指若 3 指悬空 20 mm + 2 指压入 8 mm，均值只有 +8.8 mm，落在死区（−6~+15 mm）。
限幅 ±8 mm 与问题量级（键面 P95 17–46 mm、压键数百帧）不匹配——**根因是手指弯曲不足**。

### 2.2 黑键目标抬升 → `BlackKeyTargetLift = 0`

抬 3 mm 让键面 P50 9.1 → 11.0 mm（指尖整体上移，反而更远），压键帧仅 110 → 107。
说明该曲压键的平均压入量远大于 3 mm，抬目标救不回来。

### 2.3 2.3 可达性判定的实测结论

原 (c) 类归因用键盘包围盒判定，按压点恒在盒内 → 触发恒为 0（死代码）。
改为肩距判定（含手长，`(上臂+前臂+掌长+中指) × BodyScale × 0.98`）后仍为 0——
与几何估算一致（端点按压点距肩约 0.53 m，可及半径约 0.55 m）。**当前内容没有不可达样本**。

顺带定论：换位峰值 250 mm 不是可达性问题，而是物理约束——
0.125 s（16 分音符 @120BPM）× 60 fps × 35 mm/帧 = 262 mm，正好等于峰值。
要压到 ≤100 mm 需把 `MaxStepPerFrame` 提到 ~75 mm/帧（4.5 m/s），属产品决策，未擅自改动。

## 3. 关键工程决策

### 3.1 静止手型与 CCD 初值解耦

`RestCurlDegrees` 26 → 70（MCP 25 / PIP 30 / DIP 15）。它同时是 CCD 初值，
直接改会改变收敛路径、让接触指标漂移。故新增 `SolveSeedCurlDegrees = 26`：
**观感改进走静止手型，指尖求解保持既有基线**。

### 3.2 立体声展开用声像而不是双声道波形

双声道合成让每个音高常驻内存翻倍（0.44 → 0.88 MB，极端 88 键 77 MB）。
改由播放端 `AudioSource.panStereo` 按音高分配（±0.30），听感上同样是左右分布，零额外内存。

### 3.3 URP 点光是物理单位

同样的 `Light.intensity` 在 URP 下比内置管线亮得多——实拍把琴体上半板打成黄斑、
地面过曝。加 `UrpPointLightScale = 0.42`，并让 `ApplyQuality` 重写强度时使用缩放后的值
（否则每档都被覆盖回原值）。

### 3.4 曝光三轮迭代（每轮 `--visual` 约 6 分钟，实拍判定）

| 轮次 | 观察 | 调整 |
|---|---|---|
| 1 | 地面过曝发黄、琴体上半板黄斑 | 点光 ×0.42、琴漆 0.55→0.40、Bloom 0.35→0.22 / 阈值 1.1→1.3 |
| 2 | 黄斑消失但整体欠曝（地面/背景近黑） | Trilight 三色提亮、地面反照率 0.105→0.135、背景板 0.125→0.150 |
| 3 | 曝光平衡：地面可见、琴体为深胡桃木、无过曝 | 定稿并重采 20 张基线 |

# 二期：写实观感与真人角色（同日 20:20–21:15）

一期把渲染管线追平了商业项目（URP + Linear + ACES + 反射探针），
但看图诊断发现真正的短板在**资产与几何**，不在管线。

## 诊断结论（看图得出，非推测）

| 对象 | 实际状态 | 「丑」的根因 |
|---|---|---|
| 钢琴 | 13+ 结构件其实都在（侧板、琴腿、谱架、底座、三踏板） | **全部用 `PrimitiveType.Cube`**：锐利边缘、零倒角、纯色。真实木制品没有数学锐利边，倒角捕捉的那条细高光才是实体感来源 |
| 琴键 | 尺寸符合真实（白键 24 mm / 黑键 14 mm） | 键缝看到的是木色键床，倒角 V 槽被光打亮 → 整排键像「白色梳齿」 |
| 人物 | `AvatarRigBuilder` 程序化球体堆叠 | 是**功能占位符**，不是「做得差的写实角色」。代码能生成的复杂度 = 人能写出的复杂度，写实人体需要雕刻拓扑 + 摄影测量贴图 |
| 真人模型 | Rocketbox 缺 5 张主贴图，被门禁拒绝并回落 | 网络不通 → 贴图拿不到（**本期已解除**） |

## 七项改动

1. **相机躯干避让**：判定从「中心点出视口」改为「包围盒 8 角 + 遮挡面积」，
   删除前移候选（实测是负优化：镜头贴脸时躯干落到近平面 8 cm 处，透视放大反而铺满边缘）。
   实测 Both 3.7%→2.4%。
2. **钢琴倒角化**：`CreateCasePart` 从 Cube 改 `CreateChamferedBox(AllEdges)`，
   倒角 = 最短边 15%（钳 2.5–10 mm）。AllEdges 24 顶点 == Cube 24 顶点，零预算增长。
3. **5 个结构细节**：侧臂（立式琴最醒目的识别特征）、黄铜铭牌、顶盖铰链 ×2、脚轮 ×2。
4. **琴键几何**：白键 TopOnly→AllEdges（前端圆润收边）、黑键倒角 0.6→1.2 mm、
   新增 `KeyGapShade`（键面下 3 mm 极深色薄板，让键缝读成「缝」而不是「切割线」）。
5. **程序化纹理 + 三平面 UV**：木纹/象牙/红绒 3 张运行时贴图（value noise + fbm，确定性）；
   顶点级三平面 UV 按面朝向选投影，**不拆顶点**——拆 UV 必拆顶点，共享顶点一破，
   面积加权法线的柔性倒角高光就没了。
6. **Rocketbox 真人可用化**：7 张贴图（2048² 降采样到 1024²）+ 运行时绑定 + 琴凳补全。
7. **门禁口径升级**：`ValidateMaterials` 同时认 `_MainTex` 与 `_BaseMap`；
   新增 5 例 EditMode 用例用代码构造残缺资产，把门禁两个方向都钉住。

## 三条关键技术事实（本期新认知）

**① 网络窗口**：`codeload.github.com` / `cdn.jsdelivr.net/gh/` / `api.github.com` 均 200，
只有 `raw.githubusercontent.com` 不通。jsdelivr 可逐文件代理 GitHub 内容；
16.8 MB 的单文件被主站拒（403），换 `gcore.jsdelivr.net` 镜像可拿到。

**② FBX 贴图路径永远解不到**：Rocketbox 的贴图引用是
`..\..\..\..\..\temp\Humans\with_opacity_version\f001\textures\` ——
指向建模机的本地临时目录。所以「把贴图文件放进项目」不解决问题，
必须由代码在运行时按材质名语义（body / head / opacity）从 Resources 重新绑定。

**③ 门禁与材质准备的顺序陷阱**：`ApplyTint` 原本在角色激活后才实例化材质，
而 `ValidateRig` 在此之前就检查「有没有主贴图」。必须把材质准备抽成
`EnsureMaterials()` 并在 `TryCreate` 里前置，否则门禁永远看到导入器的空材质。

## 一项「实现了但默认关闭」

**距离自适应速度**（`UseDistanceAdaptiveSpeed`）：远距离满速直线、近距离指数收敛。
A/B 实测**换位峰值几乎不动**（63.9→66.5 / 141.2→142.7 / 250.9→249.7 mm），
压键与悬空帧反而上升。结论：**提速不是瓶颈**——滞后发生在「目标何时被更新」，
不是「手腕每帧能走多远」。手正在按音时预置分支不生效，目标始终等于当前按下的键，
手腕再快也只是在追一个刚好被替换的目标。真正的修法需要预判式轨迹规划（属独立课题）。

# 三期：手部运动与几何（同日 21:00–00:10）

用户诉求「人物手部动作明显僵硬，不符合真实的物理运动规律」。定位到**数学根因**
（不是参数问题），做了两组曲线 A/B、补齐两处物理事实、三处关节几何，
并修正了一个此前一直被忽略的运动策略缺陷。

## 根因：一阶指数逼近「起步即全速」

`Lerp(cur, tgt, dt·k)` 的速度是 `k(1−k)^n` —— 第一帧就达峰值、之后单调衰减。
人手是「慢起—快中—缓停」，一阶插值缺了加速段。手指关节的 `Slerp` 同理。
**这是数学层面的僵硬，前四次调参之所以无效就是因为改的是参数量级而不是曲线形状。**

## 五项改动

| 改动 | 状态 | 依据 |
|---|---|---|
| 手指关节**二阶跟随**（标量，ω=26 rad/s） | ✅ 保留 | 键面 P95 10.2→7.4 / 10.7→4.3 / 16.2→5.6 mm（−3%/−41%/−57%），命中率持平 |
| **指腹半径 5 mm**（抬升控制目标） | ✅ 保留 | 骨骼末端贴键时指腹已压入半个指腹；P50 回到 +1.3/−1.7/−5.2 mm |
| **DIP-PIP 软耦合**（0.62 ± 14°） | ✅ 保留 | 真实 DIP 由掌腱膜被动牵拉，无法单独伸直；锁死损失可达性、放开是钩手 |
| **腕外侧背伸 6°** | ✅ 保留 | 手到键盘两端时肩-肘-腕偏离中线，需腕背伸补偿；这是「手腕与前臂不协调」的观感来源 |
| 手腕**临界阻尼弹簧** | ⚠️ 默认关闭 | 钟形起步必然牺牲换位速度（窗口仅 0.125 s≈7.5 帧）：fast_scale P95 16.7、换位峰值 255→276 |
| **空闲手位停在最后键位** | ✅ 保留 | 原实现每次音符间隙抬回键盘中央，观感是反复「抬起—落下」 |

## 一个失败方案（实现保留、默认关闭）

**minimum jerk 五阶多项式**（经典人体伸展模型）：段式规划要求目标先稳定，
而本场景目标每帧都在变（手掌修正 + 预置切换 + 连续音符）。
`LimitTargetRate` 每帧移动 25 mm 远超段重建阈值 4 mm → 每帧重建段 → 每帧返回
`current` → **手完全不动**。键面 P95 恶化到 83.6 / 56.3 / 55.0 mm，命中率跌到
88/92/76%。已完整回退，结论写进 `hand-baseline-2026-10-31.md` §5.2。

## 三处关节几何（遗留的「充气手套」项）

- **关节球**（反向半球，仅 PIP/DIP）：弯曲 30° 时相邻两段会露出硬折角与缝隙
- 环段数 10→12、段末收缩 0.88→0.93、关节加宽 5.5%→8.5%
- **删除腕部过渡球**：真实腕围是手臂最细处（收窄再展开）不是膨大。
  三次不同尺寸（薄饼/球形/扁椭球）都是鼓包 —— 球面弧线超出两侧轮廓必然读成
  「关节球」，最终靠手掌网格自身向腕后延伸覆盖交界
