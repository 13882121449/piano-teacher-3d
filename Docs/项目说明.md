## 1. 项目定位与核心功能

### 1.1 一句话定位

一个 **Windows 桌面端的 3D 钢琴演奏演示与跟练工具**：读取标准 MIDI 文件，用**唯一时间轴**驱动
88 键钢琴、程序化人物、双手手指动作、音符高亮与波形合成音，支持分手练习、变速、A-B 循环与节拍器。

### 1.2 能做什么（功能清单）

| 功能 | 具体表现 | 主要实现 |
|---|---|---|
| 曲目加载 | 读取 `.mid` / `.midi`；导入前做文件大小、音符数、时长与解析有效性校验；失败不破坏当前曲目 | `Core/SongLibraryService`、`MIDI/MidiParser`、`MIDI/MidiFileValidator` |
| 播放控制 | 播放 / 暂停 / 停止 / 重播 / 跳转（秒或 0–1 比例）/ 0.1–4.0 倍速 | `Core/LessonTimeline`、`Core/LessonSessionController` |
| 分手练习 | 双手 / 只练左手 / 只练右手：按 C4=60 过滤音符集合后重新装载调度器（对侧手既不发声也不做动作），相机聚焦活动手；该手无音符时给出提示 | `Core/PracticeHand`、`MIDI/PianoNoteFilter`、`LessonSessionController.ReloadFilteredNotes` |
| A-B 循环 | 设置 A / B 点、整曲循环、清除；循环回跳时按新时间点重建按键与手部状态 | `LessonSessionController.Update` + `ResetPlaybackState` |
| 节拍器 | 可开关、每小节拍数 1–16、强拍区分 | `Core/Metronome` |
| 琴键高亮 | 关闭 / 预提示 / 发声 / 全部四种；左手冷蓝、右手暖橙、预提示暖金 | `Piano/PianoKeyHighlighter`、`Piano/HighlightMode` |
| 键位动画 | 按键绕键根俯仰，`ReleaseAll` 立即复位 | `Piano/PianoKeyAnimator` |
| 音频 | 24 声部受控发声池，波形合成（基频 + 2/3/4 次谐波 + 指数衰减），Note Off 淡出；设备不可用时可降级静音 | `Piano/PianoAudioSynth` |
| 3D 人物 | 3 个程序化角色（写实女性 / 写实男性 / 卡通），各含 Humanoid 骨架与可见网格；切换不打断播放 | `Avatar/AvatarManager`、`AvatarRigBuilder`、`AvatarDefinition` |
| 手部动作 | 每指 MCP/PIP/DIP 三关节；指法分配 → 指尖目标 → 铰链 IK 落键；手腕受单帧位移硬约束 | `Avatar/HandIKController`、`FingerPoseController`、`FingerAssignmentService` |
| 三种视角 | 手部特写 / 全景 / 自由观察，切换不重启曲目 | `Camera/CameraModeController`、`CameraFraming` |
| 两种显示模式 | 展示（完整手部动画）/ 教学（隐藏手部，只高亮被按下琴键） | `Core/DisplayMode` |
| 曲目分析 | 音符数、左右手分布、黑键数、和弦数与最大和弦、音域、最快音符间隔、BPM 范围、总时长与练习建议 | `Core/SongAnalyzer`、`Core/SongAnalysis` |
| 偏好持久化 | 上次曲目、速度、视角、练习手、高亮、画质等 | `Core/UserPreferences` |
| 画质档 | 标准 / 高画质两档，设备推荐集中在一处判断，降档只影响阴影与抗锯齿 | `Core/QualityProfile` |
| 错误恢复 | 结构化错误码 + 中文文案 + 恢复动作按钮 | `Core/AppError`、`ErrorReporter` |
| 画质档 | 标准 / 高画质两档，集中在一处判断，不散落到各脚本 | `Core/QualityProfile` |

### 1.3 不是什么（边界）

- **不是**乐谱识别 / 音频转谱工具：只接受标准 MIDI 文件（`.mid` / `.midi`）。
- **不是**专业指法教学系统：指法由规则化启发式给出，输出置信度并标注「估算指法」。
- **不是**演奏评分器：`HandMotionReport` 衡量的是**动画质量**（指尖对键误差等），不是学习者演奏评分。
- **不含**任何第三方模型 / 贴图 / 音色采样 / 字体文件：全部程序化生成或使用引擎内置资源。

### 1.4 键盘与鼠标操作

实测自 `UI/LessonControlsUI.Update`。快捷键在焦点落在可选中控件上时会被抑制
（判据为 `!UITheme.IsSelectableFocused()`）。

| 按键 | 作用 | 代码位置 |
|---|---|---|
| `Space` | 播放 / 暂停（焦点不在输入框/按钮时） | `LessonControlsUI` |
| `[` | 重播（Restart） | 同上 |
| `R` | 重置相机 | 同上 |
| `H` | 循环切换高亮模式 | 同上 |
| `T` | 切换展示 / 教学模式 | 同上 |
| `M` | 开关节拍器 | 同上 |
| `F1` | 显示 / 隐藏帮助 | 同上 |

鼠标：底部分段控件切换视角、练习手、高亮、显示模式；自由观察模式支持拖拽旋转与滚轮缩放
（`CameraModeController` 内处理，并通过 UI 悬停隔离避免误触）。

## 3. 主要业务流程与关键设计

### 3.1 启动与场景装配

```text
MainMenu.unity
  └─ MainMenuUI（曲库 / 导入 / 最近 / 设置）
        │ 选中曲目 → 写入 MainMenuUI.SelectedSongPath
        ▼
SceneManager.LoadScene("PianoLesson")
  └─ LessonSessionController.Awake → BuildScene()   ← 11 个步骤，顺序固定
       1. LessonTimeline（唯一时间源）
       2. ErrorReporter（统一错误出口）
       3. MidiEventScheduler（唯一音符事件源）
       4. PianoKeyMap.BuildKeys()（88 键 + 琴体，居中于 X）
       5. QualityProfile.For(tier) → PianoSceneEnvironment.Build()
       6. PianoKeyAnimator / PianoAudioSynth / PianoKeyHighlighter / Metronome
       7. AvatarManager.BuildAvatars()（3 角色，位于 +Z 侧、绕 Y 旋转 180° 面向 −Z）
       8. FingerAssignmentService → HandIKController.Initialize → FingerPoseController.Initialize
       9. CameraModeController.Initialize(Camera.main, avatar, keyMap)
      10. LessonControlsUI / AvatarSelectionUI
      11. 事件连线：Scheduler.OnNoteOn/Off → 键位动画 / 音频 / 手部 IK / 手指姿态 / 高亮 / 按键集合
        ▼
LoadInitialSong() → State = Ready
```

场景文件本身几乎是空壳：只有相机、少量基础对象与一个装配入口组件（`LessonSessionController`），
**其余对象全部在运行时由代码创建**，因此「在编辑器里打开场景看不到内容」属于预期设计。

### 3.2 每帧主循环

`LessonSessionController.Update()`：

```text
current = _timeline.CurrentTime
if current < 上一帧 - 0.001      → ResetPlaybackState(); _scheduler.SeekTo(current); 相机重新取景
else                             → _scheduler.Tick(current)          # 派发 Note On/Off
UpdateHighlightUpcoming(current)  # 预提示窗口
UpdateHandLeadTargets(current)    # 手部预置（音符到来前先移动）
_metronome.Tick(current)
_handIK.Tick(current)             # 统一时间轴时间交给手部（自适应速度/指标采样）
if 教学模式 → ApplyTeachingKeySpan()   # 按当前按下的音高范围取景
OnProgressChanged(current, total)
偏好脏标记 + 节流 → SavePreferences()
```

### 3.3 音符事件链路

`MidiEventScheduler` 是**唯一**音符事件源，`OnNoteOn` 的订阅顺序固定为：

| 顺序 | 订阅者 | 作用 |
|---:|---|---|
| 1 | `PianoKeyAnimator` | 键位俯仰动画 |
| 2 | `PianoAudioSynth` | 分配声部并发声 |
| 3 | `HandIKController` | 记录按下音高、更新目标与自适应速度 |
| 4 | `FingerPoseController` | 更新共用指法分配、进入 Press/Hold 阶段 |
| 5 | `PianoKeyHighlighter` | 按左右手着色 |
| 6 | `LessonSessionController` | 跟踪当前按下音高集合（教学取景 / 一致性验证） |

`OnNoteOff` 订阅同一组对象（音频负责淡出，其余负责释放）。**不得**新增第二个时间源或第二个事件源：
`Tools/check_architecture.py` 会对「非 Core 直接引用 `LessonTimeline`」报错。

### 3.4 手部：从音符到指尖

```text
按下音高集合
   └─ FingerAssignmentService.Refresh(手, 升序音高, 时间, 帧号)   ← IK 与姿态控制器共用同一实例
        └─ HeuristicFingeringProvider.Assign() → FingerByPitch[] + Confidence + Reason
             ├─ HandIKController：第 f 指的指尖目标 = 「分配给第 f 指的那个音」的键面按压点
             └─ FingerPoseController：第 f 指进入 Press / Hold 阶段
                  ├─ 指根朝向：目标方向的水平分量 + 俯角夹在 10°–36°（不追着琴键翻转）
                  └─ MCP / PIP / DIP 绕各自局部 X 轴做铰链 CCD（6 次迭代）→ 指尖落到键面
```

关键约束与设计取舍（详见 `Docs/hand-mesh-design.md`）：

| 项 | 取值 | 说明 |
|---|---|---|
| 手腕单帧位移 | `MaxStepPerFrame = 0.035 m` | 硬约束，任何优化都**不放宽** |
| 手腕高度 / 深度 | `HandHeight = 0.799 m` / `HandDepth = 0.232 m` | 键面 ≈ 0.742 m；该组合使掌指关节落在按压点后方约 55 mm |
| 关节限位 | MCP 82° / PIP 95° / DIP 62° | 角度 ≥ 0，不允许反关节 |
| 手掌反馈 | `MaxPalmCorrection = 0.11 m` | 用指尖平均误差反向修正手腕 XZ |
| 手腕姿态 | 俯仰取角色 `HandMetrics.WristPitch`，滚转 ≤ 6° | 只改姿态，不改位置约束 |

### 3.5 相机取景

`CameraFraming` 是纯函数式取景数学（无场景依赖，可单测），`CameraModeController` 负责状态机与阻尼：

| 模式 | 关键参数（实测值） | 说明 |
|---|---|---|
| `Full` 全景 | 偏航 34°、俯角 16°、FOV 40–62°、距离 1.2–4.5 m | 跟随人物身高做轻量校正 |
| `Closeup` 特写 | 俯角 60°、FOV 30–48°、距离 0.20–0.88 m | 俯角 60° 是**几何必需**：低于约 41° 时头部会挡在相机与双手之间 |
| `Free` 自由 | 用户拖拽/滚轮，`R` 重置 | UI 悬停时屏蔽相机输入 |

### 3.6 显示模式（展示 / 教学）

| 模式 | 表现 | 实现方式 |
|---|---|---|
| `Showcase`（默认） | 完整手部与手臂动画；高亮按用户设置 | — |
| `Teaching` | **隐藏**手部与手臂网格，只高亮被按下的琴键 | 只切网格 GameObject 的激活状态，**不动骨骼与 IK** |

切换时按当前时间轴重建按键 / 手部 / 高亮状态，播放进度不变；切回展示模式无需重建，零残留。
教学模式还会按当前按下的音高范围收窄取景。

### 3.7 曲目加载事务

`LoadSong(path)` 按「校验 → 解析 → 分析 → 提交」顺序执行；任一步失败：

1. 不上抛异常，转为 `AppError`（错误码 + 中文文案 + 恢复动作）；
2. **保留**当前曲目与播放状态（不回滚成空会话）；
3. 若此前无曲目，则进入 `NoSong` 并给出「导入 MIDI / 播放示例曲」入口。

解析前由 `MidiFileValidator` 拦截：文件字节 ≤ **8 MB**、音符数 ≤ **200 000**、时长 ≤ **3600 s**、
格式/轨道/时值合法性、悬空 Note On、无速度事件等。

### 3.8 错误处理

`AppError` = `ErrorCode` + 严重度 + 用户文案 + 诊断信息 + `RecoveryAction`。稳定错误码分段：

| 段 | 范围 | 示例 |
|---|---|---|
| 曲库 / 文件 | 100–112 | `FileTooLarge=104`、`MidiNoNotes=108`、`MidiDanglingNotes=111` |
| 运行时模块 | 200–207 | `AudioInitFailed=200`、`AvatarInvalid=201`、`LoopRangeInvalid=204` |
| 未知 | 999 | `Unknown` |

恢复动作包含 `ChooseFile / Retry / ResetLoop / UseDefaultAvatar / ContinueMuted` 等，
状态栏据 `RecoveryAction` 显示按钮，会话层负责执行（`HandleRecovery()`）。

### 3.9 五条不变式

由 `Tools/check_architecture.py` 静态守护（当前 5/5 通过）：

| 编号 | 规则 |
|---|---|
| ARCH-01 | UI 不得直接依赖调度器 / 时间轴 / 琴键 / IK，必须经 `LessonSessionController` 门面 |
| ARCH-02 | 除 `Core` 外不得直接引用 `LessonTimeline`（唯一时间源只能由会话层持有） |
| ARCH-03 | 不得引入 `System.Windows.Forms` |
| ARCH-04 | 不得在 `PianoTeacher3D` 命名空间下定义与 `UnityEngine` 同名的类型（`Camera` / `Avatar` / `Light` / `Material`） |
| ARCH-05 | 表现层 `Update` 内不得出现 LINQ（热路径零分配约定） |

另有编码约定：热路径禁止每帧 `new` / 字符串拼接 / `GetComponentsInChildren`；原生对象不在字段初始化器里创建。

| 指尖对键精度 | 静态和弦实测：中指 7.4 mm、拇指 24.8 mm、小指 34.5 mm（被分配指尖口径）；播放期与换位峰值需按新口径重采基线 | 部分达成 |
| 特写俯角受限 | 相机必须位于头部之前，因此俯角固定 60°，画面偏俯视 | 已接受 |
| 接触阴影是近似 | 主光软阴影 + 贴地淡渐变薄片，**没有**真实 SSAO / 后处理 | 已接受 |
| 指法为启发式 | 输出置信度并标注「估算指法」，不承诺专业指法 | 实验性 |
| 性能数据来自批处理 | 不含真实渲染负载，未在集显 / 中档独显真机定稿 | 〔待补充〕 |
| 视觉回归靠人工 | 像素差异只作辅助，基线更新需人工确认 | 已实现 |
| 仅 Windows 桌面 | 移动端 / Web 未验证 | 计划中 |
| 无 LICENSE 文件 | 仓库当前未声明代码许可证 | 〔待补充〕 |
