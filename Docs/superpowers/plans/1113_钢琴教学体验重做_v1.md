# 🎹 钢琴教学体验重做计划

> 状态：待确认。确认后按阶段执行，每阶段保留可运行的版本和可复查的验收记录。

**目标**：让用户能看清老师用哪根手指、怎样按下琴键，并让角色、琴房和界面看起来属于同一个钢琴教学应用。

**实现路径**：曲目先生成统一的左右手和指法分配，播放过滤、键面提示和动作共用分配结果。动画按角色的骨架标定，从前臂、手腕到手指求解。界面沿用现有课程控制入口，重排页面和信息层级。

**环境**：Unity `2022.3.22f1c1`、C#、现有 URP、Windows 独立版。

## 现状与取舍

- 11 月 12 日逐指测试在 60 Hz 下采样。内置角色和写实女性的黑键离键率分别为 1.6% 和 1.1%，和弦为 13.7% 和 80.4%，快速音阶为 7.3% 和 11.7%。离键定义为按键期间分配指尖高于当时实际键面超过 6 mm。六组均无超过 4 mm 的穿键帧。[实测报告](../../reports/1112_优化验证_v3.md)
- 和弦基准里，最后一个左手八度的高音越过 C4，被现有规则分给右手。报告还记录了超出骨架可达范围的指对，以及直接旋转指根后快速音阶精度变差的实验。先解决分手与可达性，再处理剩下的悬空和腕指变形。
- 11 月 12 日的截图中，主菜单让四个入口卡和重复的曲目信息占了最醒目的区域。和弦特写能看到指节尖折、右腕偏转和头部入镜。全景旧图从背后看角色，琴体木纹和硬阴影也很抢眼。实施时先固定拍摄条件，再比较前后效果。
- 有三条路径。只换皮最快，适合作为界面试样，手部教学问题仍需另做。直接替换全部角色和渲染资源会同时引入骨架、授权和性能变量。**建议分阶段改造**，先用现有角色验证动作，再把一个新老师接入同一套测试，同时用课程页样片定视觉方向。

## 阶段 1 · 手部动作与触键

**改动入口**：`Assets/Scripts/MIDI/PianoNoteFilter.cs`、`Assets/Scripts/Core/LessonSessionController.cs`、`Assets/Scripts/Avatar/FingerAssignmentService.cs`、`HeuristicFingeringProvider.cs`、`HandIKController.cs`、`FingerPoseController.cs`、`HandPoseValidator.cs`，以及 `Assets/Scripts/Piano/PianoKeyHighlighter.cs` 和 `PianoKeyAnimator.cs`。

- [ ] 先写分手回归。覆盖左手八度跨 C4、无可靠声部信息的单轨曲、两手交错、连续重复音、切换单手练习和拖动进度。断言指定八度的两个音均属于左手，且对应音符的过滤、提示与动画一致。
- [ ] 在载入曲目时生成稳定的分配结果。有可信的分手标注时使用标注。普通 MIDI 按和弦和前后音群的连贯性、两手跨度和换位成本推断，证据不足时沿用音域规则。使用音符事件身份区分同音高的不同音符，明确同时同音的显示优先级。预提示、课程分析和演奏都读取同一份结果，切换角色时保持乐谱指法含义。
- [ ] 逐角色标定手腕中立姿态、指骨轴、指腹接触点、关节活动范围和坐姿下的有效手距。在 `HandJointPoseTests.cs`、`HandFingerCorrespondenceTests.cs` 和 `RocketboxRestPoseTests.cs` 中覆盖拇指方向、黑键落点、手腕偏转、相邻指交叉和骨长保持。
- [ ] 用和弦样本验证求解顺序。根据目标键与指骨长度筛掉不可达指法，先用前臂和腕位完成换位，再在关节范围内调整手指。按键期间跟随键面的实际运动。记录不可达音与触发原因。宽到一只手无法覆盖的输入维持可信手型、正常出声与键面提示，任何未接触的音仍计入原始统计。只有课程明确标注琶音时才按琶音演示。
- [ ] 用黑键、换指、快速音阶、重复音和跨区跳跃验证抬指、预备、落键、保持、释放。慢放检查腕臂带动换位、按键手指正确、闲置手指自然弯曲、腕掌过渡连续。用正上方检查落点，斜侧检查腕角、接触和皮肤折叠。
- [ ] **验收**：每个角色与每首基准曲分别统计，目标是超过 6 mm 的离键率 ≤ 2%，超过 4 mm 的穿键样本为 0，现有水平落点和键面距离门槛通过。新增关节越限和不可达统计。冻结采样时间、音符范围和口径，缺失指派单列并判失败。未达标就列出曲目、时间、音符、手指和失败类型，保留对照录像。

## 阶段 2 · 一个默认老师与琴房样片

**改动入口**：`Assets/Characters/`、`Assets/Scripts/Characters/CharacterRegistry.cs`、`CharacterProfile.cs`、`AvatarCharacterViewFactory.cs`、`Assets/Scripts/Piano/PianoSceneEnvironment.cs`、`PianoMeshFactory.cs` 和 `Assets/Scripts/Camera/CameraModeController.cs`。

- [ ] 先用现有角色做一版坐姿、镜头和灯光对照，同时准备一个**半写实成人钢琴老师**候选。用同一台琴、同一套镜头比较两者的正侧面、手部特写与坐姿。造型以自然人体比例、利落的演奏服和清楚的腕线为准。若需要新模型，按 [角色资产接入](../../character-asset-requirements.md) 验证可用授权、Humanoid 骨架、双手指骨与皮肤权重，记录来源。付费素材单独确认。
- [ ] 接入获选角色。校准琴凳高度、骨盆、肩肘、腕位、双脚和踏板支点。用握曲、伸指、拇指换位三种极端手型检查网格权重。新角色分配独立 ID，旧偏好仍能恢复原角色。只在候选通过验收后更新新用户默认角色。
- [ ] 琴房用深色琴体、柔和的木质背景和暖侧光。压低过强木纹、琴键反光和硬阴影，保持黑白键边界清楚。全景从斜前侧看脸、手臂与琴，手部特写检查头发、袖口和躯干遮挡。为改材质前后记录实际键面位置，保留现有触键与踏板联动。
- [ ] **验收**：交付全景、斜侧、俯视、踏板及同一和弦的前后对照。默认角色通过阶段 1 的逐指验收，坐姿贴合琴凳，脚跟和踏板接触可信，手腕皮肤在换位中无明显折叠。通过 `SittingPoseTests`、`HumanoidRigTests`、`CloseupOcclusionTests` 和角色恢复测试，最后由你看图定稿。

## 阶段 3 · 钢琴主题界面

**改动入口**：`Assets/Scripts/UI/UITheme.cs`、`UIKit.cs`、`MainMenuUI.cs`、`LessonControlsUI.cs`、`AvatarSelectionUI.cs`、`FileBrowserUI.cs`，以及 `Docs/ui-design-system.md`。

- [ ] 先做主菜单和课程页两张样片。推荐「钢琴练习室」方向：琴漆黑、象牙白、胡桃木，少量黄铜强调当前动作。使用项目内琴体渲染建立钢琴主题。已有左手冷蓝、右手暖橙、即将落键暖金的含义继续沿用，配文字或图标区分状态。
- [ ] 首页把「继续练习」作为主操作。没有历史曲目时主操作改为「开始示范」。曲库只出现一份，导入 MIDI 紧挨曲库。角色、画质和快捷键放在次级入口，移除重复曲目说明和底部长条提示。
- [ ] 课程页让双手、琴键和教学标记占据画面中央。底栏保留播放、时间轴、左右手、速度和 A/B 循环，视角放在特写附近的固定入口。分析、节拍器、角色切换和设置分组呈现。角色卡用实际模型渲染缩略图。保留现有会话命令和快捷键，弹层关闭后焦点返回触发按钮。
- [ ] **验收**：1280×720、1920×1080 和文档约定的紧凑窗口分别跑一遍。检查中文长曲名、空曲库、导入失败、加载、暂停、弹层与键盘焦点。默认布局无裁切、控件重叠或手部遮挡，普通文本与背景对比度至少 4.5∶1。用户从首页能直接进入示范或继续练习，从课程页可完成暂停、降速、切单手和设置循环。用 `UIThemeTokenTests`、`MainMenuLibraryTests`、`TeachingFeatureTests` 与截图复核。

## 阶段 4 · 练习流程与交付

- [ ] 用现有慢速、单手和循环能力串一次完整练习：选曲 → 看示范 → 手部特写 → 降速 → 选单手 → 设置 A/B 循环 → 恢复双手。检查拖动进度和循环回跳后的音频、键面、指法提示和手型在同一时点恢复。用一份现有 MIDI 覆盖导入、重开和设置保存。
- [ ] 在仓库目录跑 `python Tools/static_checks.py`、`python -B -m unittest discover -s Tools/tests -p test_1112_verify_v1.py`、`python Tools/verify.py`。核对静态检查、编译、EditMode 与完整 PlayMode，记录所有跳过项及原因。
- [ ] 在有 GPU 的环境跑 `python Tools/verify.py --visual`。人工确认新画面后再更新截图基线，用 `python Tools/verify.py --compare-visual` 验证后续回归。视觉对照统一使用同一角色、机位、分辨率和曲目时间，动态手型另附原速和慢放录像。
- [ ] 运行 `python Tools/verify.py --player`。在实际 1280×720 Windows Player 内验证普通播放和切换都采满至少 100 帧、p99 ≤ 20 ms、1% low ≥ 55 FPS。手动冷启动、播放首个和弦、切曲、切角色、切视角、退出并重新启动一次。若出现崩溃，保留日志，记录复现条件。集显成绩单独报告实际设备及结果。
- [ ] 按 [运行与验证指南](../../how-to-run.md) 构建 Windows 使用版到 `Builds/Windows/` 的本轮子目录。交付版、对照图、手部数据和验证报告各有明确路径。报告列出修改文件、各角色各曲目的实测值、各项通过或失败，以及未运行的检查。

## 本轮待确认的方向

- 优先级建议：先完成阶段 0 和手部方案的首个可运行样本。界面样片可使用现有场景，角色替换以同一套动作验收为准。
- 美术建议：先集中做好一个半写实成人老师与一间暖光琴房。等模型和机位通过特写验收，再决定其他角色是否沿用该风格。
