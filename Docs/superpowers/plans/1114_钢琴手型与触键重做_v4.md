# 钢琴手型与触键重做计划

> 受限手型和联合腕位已进入独立预览。短样本的三角色总体仍未达到课堂切换标准。见 [v7 验收](../../reports/1114_钢琴手型预览验收_v4.md) 和 [v8 验收](../../reports/1114_钢琴手型联合腕位验收_v5.md)。

**目标**　让三种角色能用符合人体关节方向、手掌跨度和演奏节奏的手型演示常见钢琴指法，并能明确指出超出当前角色能力的音符。

**实现路线**　加载乐曲时先规划一段连续的指法与双手位置。播放时按乐曲时间采样同一份轨迹，用角色自身的骨骼约束贴合实际键帽。现有 Unity 课堂、发声、琴键和回放入口继续使用。

## 1. 复现截图中的手型

图中两手在键面中央挤到一起，个别指根明显横偏，手指张开和弯曲的组合不适合用作正常教学示范。截图没有曲名、时间或键位记录，还不能判断原音组是否可由真人正常弹出，也不能仅靠单帧确认是否穿键或发生拇指穿指。

- [x] 从 v6 的演示曲、三首基准曲和角色库中查找相似帧。若找不到原帧，用相邻音区同拍和弦加跨拇指的最小 MIDI 复现、保存角色 ID、曲目、音符事件和时间，标记为重建用例。
- [x] 给现有诊断补充按帧输出。记录每手每指的 MIDI 音高、活动或预提示状态、键帽内落点、关节相对绑定姿态的旋转和腕位、掌部与指节间距。镜头同时保存俯视和斜侧两张图。亮键颜色可辅助读图，真假按键以 MIDI 和实际键行程为准。
- [ ] 用同帧对照验证三个嫌疑。分别检查动作规划的指法、和弦腕位、以及指根贴键修正前后的关节角与碰撞。现有 `FingerPoseController.ConstrainFingertipContact` 会在解算后写回指根旋转，`HandIKController.TryPlaceChordWrist` 以当前指根估计腕位，`FingerAssignmentService.PreviewFinger` 控制预备指。这些是检查入口，截图本身不足以判定根因。
- [x] 把已定位的错误变成 `HandFingerCorrespondenceTests.cs` 或 `HandBenchmarkTests.cs` 中先失败的用例。保存 v6 的同位置关键帧和触键统计。

## 2. 验证外部方案

- [x] 用同一份项目 MIDI 对照 PianoPlayer 输出和当前指法。PianoPlayer 是 MIT 许可的 Python 指法工具，可导出标注，支持手尺寸预设；它的 3D 预览不能直接作为现有三套角色的 Unity 动画驱动。重点对照和弦、左右手相邻音区、同指重复与上行下行穿指。先独立运行、记录版本和结果，再决定采用它的输出还是把有收益的规则移植进 C#。 [PianoPlayer 仓库](https://github.com/marcomusy/pianoplayer)
- [ ] 将 Hand-thesia 3D 的公开示例与本项目同视角比较，重点看闲指、重叠手位和起音接触。其 Blender 离线流程接近目标画面。README 说明负责指法与手部动画的上游 Hand-thesia 未附许可，因此只做观察和方案对比。 [Hand-thesia 3D 仓库](https://github.com/mrbobbrick/3D-piano-animator#credits-and-license)
- [ ] 用 FürElise 的公开演奏查看腕部换位、黑白键深度差和空闲指走势。数据包含同步 MIDI 与手部三维关节，许可为 CC BY-NC 4.0。计划通过公开样例做参考，演示工程使用自制或另行授权的动作片段。Tipiano 作为指尖先约束、再生成腕和关节的技术参考，接入前需看到可用代码、权重与对应许可。 [FürElise 数据说明](https://huggingface.co/datasets/rcwang/for_elise/blob/main/README.md) [Tipiano 技术资料](https://arxiv.org/abs/2604.09692)
- [x] 记录仿真路线的取舍。RoboPianist、PianoMime 与 MUSIC 有公开实现，可借鉴接触、碰撞和约束测试。其仿真手、运行时及训练方式与 Unity 三角色不同，更适合作为参照。 [RoboPianist](https://github.com/google-research/robopianist) [PianoMime](https://github.com/sNiper-Qian/pianomime) [MUSIC](https://github.com/xupei0610/music)

## 3. 先通过指法与双手可达性

- [x] 在现有 `Assets/Scripts/Avatar/FingerAssignmentService.cs` 与课程准备流程中，给每个音符建立稳定的手别、指号和起止时间。按乐句或短窗口前瞻，和弦组合优先检查指序、有效跨度、黑白键深度和目标点；同音重复按音符事件区分。持续音保留指号，明确编排的换指单独建事件。
- [ ] 按实际骨长、手掌宽度与当前琴几何为三角色分别求解。双手进入同一区域时，优先换可行指法或调整手掌位置。真实交叉动作须检查两手在不同深度或高度通过时的间隙。
- [ ] 可行候选用移动距离、关节偏离自然姿态的程度和下一组音的准备代价排序。无法覆盖的导入曲保持原 MIDI 的声音及键盘提示，标出该段无可行演示指法。未经用户选择，避免把同时和弦改成琶音或擅自省略音符。
- [x] 先验证单手 C 大调音阶、含黑键三和弦、同指重复、双手相邻以及故意超跨度的 MIDI。保留可行和不可行两种测试。

## 4. 用同一套约束生成腕、掌和手指姿势

- [ ] 在 `HandIKController.cs`、`FingerPoseController.cs` 和现有 Rocketbox 骨架适配层，按手骨坐标应用屈伸、侧摆、拇指对掌与腕部角度限制。联合求掌位和活动指，先把正确键帽与关节范围作为约束，再选自然的腕位和闲指姿态。对人体跨度不足的候选回到指法规划。
- [ ] 将活动指指腹约束到对应键帽可触区域，黑键使用自己的高度与前后范围。目标位置随实际键的下压和回弹更新。增加相邻手指、两掌、手腕和黑键侧壁的碰撞检查。把现有求解后额外扭转指根的行为移入受限求解，避免贴了键面却横跨到邻键。
- [ ] 生成预备、接触、压住、释放轨迹。先限制活动指稳住键帽，再允许空闲指和手腕为下一组音准备。用曲目时间采样姿态，验证暂停、拖进度、调速、循环和换角色后同一时刻的重建一致性。
- [ ] 若三角色中只有一个异常，先检查其关节轴与网格蒙皮。用骨架线视图和网格图对照，确认截图中的手指挤叠、网格折痕分别来自哪里。

## 5. 先验收短样本，再进课堂

- [x] 先交一个可重复的短演奏样片，以同一 MIDI、同镜位展示 v6 和新版原速与半速。包含截图同类场景、普通和弦、黑白键切换与拇指穿指，提供俯视、斜侧与挂接到实际键帽的指号视图。
- [ ] 固定 60 Hz 测试三角色，记录每首曲的合格帧与总采样帧。对事先标定为可演奏的教学样本，建议验收值为有效保持期正确键帽率至少 95%，正确接触耗时 P95 不超过 2 帧，任一活动指离键超过 6 mm 的帧不超过 2%，穿键超过 4 mm 的帧为 0。不可行音符单独报告，不能从原本可演奏的样本里剔除失误。
- [ ] 用角色专属关节上限和碰撞检查拦截反折、过度侧摆、手指相穿与双掌重叠；同时和真人片段对照腕位、触键及释放。接触数据通过后仍须检查原速和半速画面，尤其是双手靠近时。
- [ ] 短样本达标后再接入课堂。运行 `python Tools/verify.py`、三角色触键专项、图形快照和 Windows 启动，报告仍有偏差的曲目。保持音频、速度、循环、踏板和角色库入口的现有行为，技术实验失败时保留可运行的 v6 作为对照。
