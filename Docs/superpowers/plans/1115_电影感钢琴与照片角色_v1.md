# 电影感钢琴与照片角色实施计划

**目标**：做出一段可以在 Windows 使用版中实时播放的海底钢琴样片，再加入随曲变化的舞台和从照片创建可弹琴的角色。

**架构**：琴壳美术模型与物理琴键分开。演奏时间轴同时驱动灯光、布景和自动机位。照片角色采用已校准骨架，外观拟合与触键解算各自负责自己的数据。

**技术**：Unity 2022.3.22f1c1、现有 URP 14.0.10、Blender、Unity Recorder。先用现有相机控制器，演示机位需要独立轨道时验证 Cinemachine 与当前版本的兼容性。计划内的画质与性能数字是验收目标。

**v18 实施记录**：本机未找到 Blender，琴壳改用 Unity 可复现的独立网格与原创木纹制作，视频用 Unity 编辑器自带编码器导出。舞台随曲变化和自动运镜已接入正常菜单。照片首版采用离线八点辅助拟合，自动人脸检测、真人相似度和照片角色多曲触键误差保留待验。实际产物、差异和验证依据见[验收记录](../../reports/1115_潮光电影舞台验收_v1.md)。

## 现状与路线

- 现有弧架琴在 `Assets/Scripts/Piano/PianoKeyMap.cs` 中由网格代码组合。近镜头要靠细分合理的轮廓、真实接缝、分材质和映出场景的高光。建议在 Blender 做原创的「深海弧架三角琴」，参考真琴内部结构。检索到的 [Sketchfab Grand Piano](https://sketchfab.com/3d-models/grand-piano-4ce9e8dbeb74425eb215e4168807dcb5) 作者页标注 CC Attribution，约 61 万三角面，适合评估结构与重拓扑。若复用其几何，先核对下载包、许可和署名要求，再进项目。[Unity 反射探针](https://docs.unity3d.com/cn/2022.3/Manual/RefProbeTypes.html)
- `UnderwaterStage.Update()` 用运行时间循环驱动生物，场景构图和灯光配置没有随曲段变化。可以借鉴 Unity 官方 URP 样例的机位与后处理切换，再把变化接到项目已有 `LessonSessionController.CurrentTime`。[Boat Attack](https://github.com/Unity-Technologies/BoatAttack) · [Cinemachine](https://docs.unity3d.com/2022.3/Documentation/Manual/com.unity.cinemachine.html)
- 照片角色有三条路。**首版做本地头像拟合加标准演奏身体**，把照片中的五官和脸型特征转为模板头部参数，发型与服装可选。**更写实的候选是 Avaturn**，官方提供自拍生成和 GLB，但 Windows 独立版需单独确认接入，真实样本要验证手指骨、授权和照片处理条款。**整身重建是研究路线**，SAM 3D Body 能恢复单图的人体网格与姿态，产品仍需处理遮挡部位外观、重建后绑定、蒙皮、单独的权重许可和硬件要求。首版的人脸相似度以实际预览与用户判断为准。[MediaPipe Face Landmarker](https://ai.google.dev/edge/api/mediapipe/python/mp/tasks/vision/FaceLandmarkerResult) · [Avaturn Unity 指南](https://docs.avaturn.me/docs/integration/unity/demo_project/) · [Unity glTFast](https://github.com/Unity-Technologies/com.unity.cloud.gltfast) · [SAM 3D Body](https://github.com/facebookresearch/sam-3d-body)

## 阶段一 · 先做一段能进游戏看的样片

- [x] 按用户给的参考图和本地视频提取 3 到 5 个关键镜头，记录琴体占画面比例、高光方向、前中后景、镜头移动速度。选项目内一首曲子，固定 v17 对照画面、同一人物、同一曲段和相近视角。
- [ ] 在 `Assets/Art/Piano` 制作琴体 FBX、材质和预制件。主轮廓由连续曲面形成，外壳做细倒角和多层厚度。做出琴盖边缘与铰链、音板木纹、拉丝黄铜弦轴、弦列、踏板与三脚连接结构。用不同粗糙度区分亮漆、金属、木材和琴键。主镜头用烘焙或手工配置的反射探针，近镜头检查反射走向、接缝和倒角。为全景准备低细节模型。
- [ ] 让 `PianoKeyMap` 用独立外壳预制件替换原展示琴壳。比对全部 88 个键的静止位置及按下终点，并校验琴凳和踏板接触点。白键、黑键、三踏板与手部示范仍走现有逻辑。检查俯视、拍手侧视和最低最高音，排除琴壳挡手或挡键。
- [x] 做出约 20–30 秒样片，用统一的曝光、色彩和环境反射。镜头顺序是低机位展示弧架和高光 → 侧后方揭示鲸鱼和光束 → 键盘近景展示触键 → 全景收尾。先在 Windows 实时运行，再录制 1080p 视频佐证。拍手镜头的焦点落在琴键与手指上，课程镜头保持可读的景深和亮度。[Unity Recorder](https://docs.unity3d.com/Packages/com.unity.recorder@4.0/manual/index.html)
- [ ] **通过标准**：同曲段和机位交付 v17／新版视频及琴体三张近景。近距离能分辨琴壳边缘、弦轴、弦和踏板，转动镜头时漆面高光自然移动。以用户对样片的观感为扩展依据。

## 阶段二 · 让海底布景随曲子变化

- [x] 新增 `Assets/Scripts/Piano/StageSequence.cs` 和 `StageSequenceProfile.cs`。给样片曲目手工标注三个段落。序奏是浅蓝晨光、疏散的小鱼。展开段逐渐加深景深层次，鱼群从侧面经过。情绪高点安排后景鲸鱼经过光柱，尾声逐渐收回光强和生物密度。灯光、水雾、鱼群路径、暗处发光生物和镜头构图共同变化。
- [x] 让 `LessonSessionController` 提供曲目时间，`UnderwaterStage`、相关材质和 `CameraModeController` 读取同一个时间状态。暂停时保持段落和自动机位。拖动或循环时按目标时间直接取样，避免鲸鱼事件依赖先前经过的帧。切换曲目后从其初始段落重置，未配置曲目用通用三段预设。过渡做缓变。教学课固定机位与稳定曝光，用户可关闭演奏自动运镜。
- [ ] **通过标准**：同首曲子在首、中、尾截图中能看出构图、用光和生物活动的变化。在不同顺序拖到同一时间点，应得到相同的段落状态和动物位置。覆盖暂停、倍速、前后拖动、练习循环、切曲和换角色，琴键提示始终可见。

## 阶段三 · 导入照片生成可演奏的角色

- [x] 在 `Assets/Scripts/UI/AvatarSelectionUI.cs` 加「从照片创建」。流程为选择 JPG 或 PNG → 裁切与画质检查 → 预览正面与侧面 → 调整发型、肤色和服装 → 保存到角色库 → 上台弹奏。首版使用清楚的单人正脸。对大文件、损坏图片、无脸、多人和侧脸给出重选或重拍提示，取消后返回原角色。
- [ ] 先用 MediaPipe 的本地人脸关键点验证离线拟合。拟合五官和脸型，提取配色与可用的外观细节，让预览在转头后仍有立体轮廓。检查模型和运行时的部署许可、Windows 离线安装体积及推理延迟。原图只在生成过程中读取，保存用户确认的外观参数和生成资产。提供角色移除入口。若离线表现不够理想，再用明确同意的授权样本单独评估云端方案的效果、费用和数据处理方式。
- [x] 通过 `Assets/Scripts/Characters/ICharacterRigSource.cs` 与 `AvatarManager` 接入固定比例的演奏骨架，让项目的手指逆向运动学和 `PedalFootAnimator` 驱动每个角色。校准肩、肘、掌、两手十指与右脚踩踏板的位置。若评估外部全身 GLB，先过骨架门槛，缺指节或蒙皮异常时使用已校准的演奏身体。
- [ ] **通过标准**：至少 3 张有授权且外观差异明显的有效样本能创建、保存、重启后重新选用。本人或评审从正面与侧面检视辨识度。每个样本都要能完成单音、和弦、快速音阶和有延音踏板的片段。跑同一组内置角色的触键对照，记录穿键超 4 mm 的次数及悬空率，舞台改动不得增加超限次数，照片角色的悬空率应达到同骨架的内置角色水平。对错误图片和中断生成做回归。有照片生成就验证本地路径在断网时仍能完成。

## 交付与性能验收

- [x] 以本机 Windows 同分辨率、同曲段、同角色的 v17 为对照，录 60 秒展示和练习。标准档首轮目标为 1080p 第 95 百分位帧耗时不超过 33.3 ms，同时记录 GPU、显存和切镜头尖峰。优先降低远景生物网格复杂度、散射分辨率和探针刷新频率，保护琴体和手部清晰度。
- [ ] 跑 `python Tools/verify.py` 和单独 GPU 图形验证，重新打包 Windows，实测启动与退出、演奏展示、第一课、换角色、曲段拖动和演奏恢复。把新版程序放进 `Builds/Windows/`，视频和性能数据放进 `_verify_out/`，验收报告放进 `Docs/reports/`。
