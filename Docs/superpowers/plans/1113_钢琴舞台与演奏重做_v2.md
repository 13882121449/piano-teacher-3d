# 🎹 钢琴舞台与演奏重做总计划

> 本文为待确认的总计划。实施时用 executing-plans 或 subagent-driven-development 按工作包执行，各包都有独立可运行的验收样片与检查项。

**目标**　重做首屏、换成真正有辨识度的演奏舞台，并把手、琴键、脚和踏板做成可信、可慢放观察的实时演奏。

**实现思路**　首页使用独立舞台构图，课堂保持可读、可操作。钢琴琴壳和灯光作为场景层，88 键与踏板接触点作为演奏层。音符、手指、琴键、音频和踏板共用课程时间轴，骨架和材质分别验收。

**技术范围**　Unity 2022.3.22f1c1、URP、C#、Blender 资产预处理、Windows 本地使用版。

## 1. 方向与当前差距

- **主方案 · 蓝黑三角琴舞台**。首页右侧用巨大开盖三角琴虚影和一圈冷蓝轮廓光，琴键带从右下向纵深螺旋下沉，左侧留给「开始示范」「继续练习」和曲库入口。课堂使用同一台黑漆三角琴，在小型音乐厅内搭建木地板、吸音墙、帘幕和暖白主光。高光收在琴盖边沿，手和键面保持清楚。
- **另一种方向 · 纯未来键盘隧道**。用全屏螺旋、节拍光带和高饱和色做首页，动势更强，文字和控制较难在任意画幅保持清晰。取其中的螺旋动效用于主方案首页，也用在进入课程的短过渡。
- **另一种方向 · 暖色录音室**。采用木色三角琴、窗光和近距离机位，适合长时间练习，首屏冲击力较弱。低画质或减少动效模式借用它的静态构图。
- 上一版重点修了穿键，默认女老师和弦仍有 159/346 帧高于键面 6 mm，快速音阶为 9/249。现有 40 mm 静态距离测试可保留做回归，但它无法评价换指、指腹落点和腕部节奏。手部这次增加原速、慢放、逐事件数据三种验收。
- 脚部已经有延音区间、右腿两骨求解和踏板动画。当前会话只在尚未绑定时查找脚骨，踏板则按场景对象名绑定。换角色、换琴或切换播放状态时的绑定与重建需要专项复现。现有角度驱动还需检查实际鞋底是否跟着踏板接触面移动。[上一版验收报告](../../reports/1113_钢琴教学体验验收_v1.md)

## 2. 可借用的素材和代码

- **三角琴首选候选**。Innerscene 的开盖三角琴是无品牌、带材质的 3.8 MB GLB，资产页标明 CC0。先在 Blender 检查琴壳、键盘和踏板能否分离，量测键盘、琴凳和踏板相对位置。即使素材只有合并网格，也可以保留可用的琴壳，使用本项目的 88 键和独立踏板。轮廓、琴盖和腿部遮挡不合格时，自建简化外壳。[Innerscene 原始资产](https://www.innerscene.com/tools/library/3d-parts/grand-piano-open-lid-b0c88240)
- **GitHub 可借用候选**。piano-gl 的作者标明琴模为 MIT，库本身是 OpenGL 渲染方案。检查仓库的模型轮廓和键帽细节，若模型适合可转为 Unity 资产并保留许可。Unity 继续使用项目现有的键面动画与渲染链。[piano-gl 资产声明](https://github.com/dr-inf/piano-gl#assets)
- **动作参考**。Hand-thesia 适合参考拇指穿指、重复和弦回弹与颤音前臂旋转。其上游缺少代码许可证，3D 衍生项目以 Blender 离线渲染为主。只观看公开演示并自行实现，保留原始 MIDI 音频语义。[Hand-thesia](https://github.com/V9011N/pygame-piano-animator) · [3D 衍生项目与许可说明](https://github.com/mrbobbrick/3D-piano-animator#credits-and-license)
- **角色候选与场景**。Blender 官方 CC0 Human Base Meshes 可用来检查手掌比例、换手网格或制作一个半写实老师候选。需要另外做绑定、蒙皮和服装。Poly Haven 的 CC0 木质摄影棚 HDRI 可供琴漆反射测试，音乐厅墙面和遮挡按课程机位搭建。[Blender 官方资产](https://www.blender.org/download/demo-files/#assets) · [Poly Haven 灯光参考](https://polyhaven.com/a/wooden_studio_01)
- **腿部求解备选**。先修现有两骨求解。若在新踏板几何下仍无法稳定锁住脚跟和脚掌接触，可在隔离场景对比 Unity 2022.3 支持的 Animation Rigging 1.2.1 Two Bone IK。确认执行顺序、原有动画和构建开销后再决定是否加依赖。[Unity 版本说明](https://docs.unity.cn/Manual/com.unity.animation.rigging.html) · [Two Bone IK](https://docs.unity.cn/Packages/com.unity.animation.rigging%401.2/manual/constraints/TwoBoneIKConstraint.html)
- 入库前逐项记录作者、原始链接、版本或提交 SHA、许可、文件哈希和本地改动，更新 `Docs/asset-licenses.md`。本轮调研仅核对来源及声明，资产的网格结构、Unity 导入和动作适配在样片中验证。

## 3. 实施顺序

### A · 固定样本与旧版录像

涉及 `Assets/Tests/PlayMode/HandBenchmarkTests.cs`、`VisualSnapshotTests.cs`、`PedalFootRocketboxTests.cs` 和 `Tools/verify.py`。

- [ ] 保留现有工作树与上一版 Windows 包。用 1280×720 同机录制旧版首页、全景、手部俯视、斜侧及踏板。锁定角色、镜头、时间、光线与播放速度。
- [ ] 固定三首现有基准曲，追加六个自制短样本。样本覆盖同指重复、相邻指颤音、拇指穿指、断奏与连奏、大跳、带 CC64 的反复踩放。另造连续和弦且没有 CC64 的样本，比较自动踏板开关。
- [ ] 补记录音高、左右手、指号、起止时间、落键延迟、水平落点、垂直离键、穿键、双手重叠和关节角速度。报告同时列出全程统计及起音后接触阶段，记录缺失指派和不可达原因。

### B · 首页重做与舞台样片

涉及 `Assets/Scripts/UI/MainMenuUI.cs`、`UITheme.cs`、`LessonControlsUI.cs`、`Assets/Scripts/Piano/PianoSceneEnvironment.cs` 和 `Assets/Scripts/Camera/CameraModeController.cs`。

- [ ] 在首页做「巨琴虚影」和「巨琴虚影加螺旋键带」两张同文案样片，以及 5–8 秒循环动效。巨琴轮廓与课程用琴一致。螺旋放在右侧和下方，可用少量共享琴键网格或预渲染循环，实测后选成本较低的实现。
- [ ] 首页保留清晰主按钮、单份可滚动曲库与导入入口。课堂保留稳定时间轴、速度、左右手、A/B 和镜头，螺旋效果在进入课堂后结束。提供减少动效选项及静态画面，焦点和提示不随背景移动。
- [ ] 设计一间有前中后层次的小型音乐厅。前景保持键盘和手腕，中景展示琴体、琴凳和踏板，后景用帘幕、声学墙和灯光形成深度。限制高反光与高亮区域。
- [ ] 通过 960×720、1280×720、1920×1080 的首页和课堂截图，检查长中文名、键盘焦点、导入反馈和弹层。正文对比度至少 4.5∶1，实测控件可点击。录下首页动效打开和关闭的对照。

### C · 三角钢琴与人物造型

涉及 `PianoKeyMap.cs`、`PianoMeshFactory.cs`、`PianoKeyAnimator.cs`、`SittingPoseApplier.cs`、`CharacterRegistry.cs` 和 `Assets/Characters/`。

- [ ] 将新琴拆成固定琴壳、可独立转动的键和踏板。保持 MIDI 21–108 的一一映射，逐键检查运动方向、白键与黑键表面采样、琴壳间隙和动键颜色。
- [ ] 在琴预制品或场景构建层定义键盘、琴凳、脚跟和三枚踏板铰链及鞋掌接触点。用这些标记重标坐姿、膝肘位置和机位。全景看得到琴盖和人，特写看得清左右手，踏板机位能同时看到鞋跟、鞋尖和踏板。
- [ ] 做一个半写实成人老师样片，至少检查脸、手、袖口和坐姿，保留原角色 ID 可恢复。新候选使用独立 ID。比较伸指、弯指、八度、拇指穿指和踩踏板时的皮肤形变。候选通过动作和画面验收后才替换默认角色。
- [ ] 扩展 `SittingPoseTests`、`CameraVisibilityTests` 和 `VisualSnapshotTests`。覆盖琴盖、谱架与袖口遮挡、不同体型的琴凳高度以及踏板脚部机位。

### D · 手部演奏重做

涉及 `Assets/Scripts/Avatar/HeuristicFingeringProvider.cs`、`FingerAssignmentService.cs`、`HandIKController.cs`、`FingerPoseController.cs` 和 `HandPoseValidator.cs`。

- [ ] 在加载时按乐句准备指法和换位轨迹。保留同音重叠语义，给连奏、重复、穿指和跨度过大设不同代价。先用连续音群和左手八度建立失败用例，再调整分配。
- [ ] 拆分「准备动作」与「接触约束」。让前臂和手腕提前换位，按音符时值和力度控制抬指、下键、保持与释放。拇指穿指先改变掌向，颤音加入受限前臂旋转，重复和弦加入小幅回弹。其他手指可有少量联动，已按住的指腹保持接触。
- [ ] 在新角色上校准指腹位置、指骨轴、关节范围和腕掌中立姿势。落键时约束指腹在对应键帽可演奏区域内，键下沉时追踪当帧表面。优先修右手小指，查出水平和垂直误差各来自哪里。几何超限照常播放并报告，不伪造触键或修改原曲起音。
- [ ] 验收以两种已支持骨架、三首原基准曲加新短样本为准。原六组各自要求 **超过 6 mm 离键率 ≤2%、超过 4 mm 穿键为 0**。另测稳定按压帧中指腹落在正确键帽区域的比例，目标至少 95%。起音同步用固定 60 Hz 逐帧测，目标可达音符的落键误差 P95 ≤2 帧，报告超限音符与原因。
- [ ] 提交原速与 0.5× 对照视频。逐段检查腕臂是否先于换位、快速音阶是否每指可辨、手指是否互穿、保持时是否抖动、腕指是否突跳。数值与视频一起验收。

### E · 脚、踏板和延音

涉及 `Assets/Scripts/Characters/PedalFootAnimator.cs`、`Assets/Scripts/MIDI/MidiParser.cs`、`LessonSessionController.cs`、`PianoAudioSynth.cs` 及 `PedalSustainTests.cs`、`PedalFootRocketboxTests.cs`。

- [ ] 先写换角色仍踩延音、换琴重新绑定、暂停和拖动进入踏板保持区间的回归。让右脚绑定随当前角色视图变更，踏板绑定直接读取当前琴的标记。无可动脚骨的旧角色保留踏板运动并明确标识支持范围。
- [ ] 从同一课程时刻求踏板状态并供音频和动画使用。CC64 优先，暂停冻结并在 Seek、循环回跳或换曲后按目标时刻重建。未带踏板数据的曲目保留原演奏，提供单独的自动延音演示选项。
- [ ] 让脚跟在地面附近形成支点，脚踝和前脚掌带动踏板下压并跟随回弹。左脚稳定支撑，身体只做轻微重心变化。先保证延音踏板，左、中踏板在没有对应数据时保持静止。
- [ ] 验收同时拍鞋底和踏板。正常踩住时鞋掌与踏板接触点误差目标 ≤10 mm，脚跟无明显漂移，动作和踏板位移起点相差 ≤2 帧（60 Hz）。用显式 CC64、无 CC64、暂停、拖动、循环回跳和换人验证动作与音频状态。

### F · 练习体验与交付

涉及 `Assets/Scripts/Core/LessonSessionController.cs`、`UserPreferences.cs`、`SongLibraryService.cs`、`MainMenuUI.cs` 和 `Tools/verify.py`。

- [ ] 增加手指编号开关和独立踏板视角，颜色沿用左右手语义。键帽上只给当前音或下一音标号，避免快段堆满数字。
- [ ] 把「继续练习」从本次会话记忆扩展成跨重启恢复。保存曲目标识、播放位置、速度和分手。曲目仍存在时打开后停在上次位置，文件缺失时提供重新导入。
- [ ] 跑静态检查、Python 验证脚本测试、全量 EditMode/PlayMode、显式逐指诊断、画面快照与 Windows 性能。1280×720 高画质继续要求 p99 ≤20 ms、1% low ≥55 FPS；另记录 1080p 和低画质实际数据。性能样本同时覆盖首页动效与课堂播放、换角和换机位。
- [ ] 用使用版实测首次启动、导入、跟练、A/B 循环、切角、切视角、退出和重启恢复。把包放进新的 `Builds/Windows/` 子目录，报告包含源文件、资产许可、截图、原速及慢放视频和实测数据。各阶段以可运行样片核对，任一核心指标或画面未通过时逐项记录。

## 4. 首个样片的范围

确认后先并行验证两件事。第一件是开盖三角琴与首页两套构图，第二件是同一段和弦、音阶和踩踏板在原速及慢放下的动作。先确定可读性、琴键空间和动作上限，再给全场景、其他曲目和角色扩面。交付时以这组样片与上一版的同机位对照作为主要验收依据。
