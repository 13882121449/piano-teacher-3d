# 资产许可证清单（asset-licenses.md）

> 对应方案 **2.1 设计原则「遵守资源许可证」**、**5.2 中期「为人物和钢琴分别建立资源适配层」**、
> **6.5 资源评估原则**、**7.3 音频优先级**、**9.2 用户数据与内容分离**；审查 **1.1 方案 B**「模型、贴图、字体及其他资产的来源与许可证登记在 Docs/asset-licenses.md」。
>
> **核心原则：代码许可证（MIT / Apache-2.0）不等于资产许可证。** 引入任何外部资源时必须按本文件第 3 节**分类型**登记，
> 并把「代码」「模型」「贴图」「动画」「骨架权重」「音色采样」「字体」当作**互相独立**的资产分别核对。

## 2. 已声明「零第三方包」的范围

- `Packages/manifest.json` 未引入任何第三方 Unity 包（仅 Unity 官方模块）。
- `Tools/*.py` 使用 Python 3.8+ **标准库**（`argparse / os / subprocess / sys / time / xml.etree / pathlib`；`visual_diff.py` 用 `zlib + struct` 手写 PNG 解码），**不需要 pip 安装任何包**。
- 未使用 `System.Windows.Forms` / `OpenFileDialog`（应用内文件选择器自建）。
- 未使用 TextMeshPro / 任何 UI 素材包。

## 3. 引入外部资源的登记流程

### 3.1 总则

1. **分类型登记**：一次集成若同时引入模型 + 贴图 + 动画，必须**逐类登记**，不能只登记「代码许可证」。
2. **固定版本**：登记固定 commit / release 版本（不要写「主分支」），并保存许可证原文或链接。
3. **商业与再分发**：明确是否允许商业使用、修改、再分发，是否要求署名 / 附带许可证。
4. **不进入正式构建**：无授权资源不得进入正式构建（方案 15 章发布前检查清单）。

### 3.2 按资产类型的登记要求

| 资产类型 | 必须登记的内容 | 特别注意 |
|---|---|---|
| **代码 / 库** | 仓库地址、固定 commit/release、代码许可证（MIT / Apache-2.0 等）、版权声明、依赖树（各依赖各自的许可证）、Unity 版本兼容性、性能 / 安全风险 | 代码许可证 ≠ 其依赖或随附资源的许可证 |
| **模型（网格）** | 模型来源、许可证、是否允许修改 / 再分发、是否含第三方商标 / 角色形象、三角面数与性能预算 | 「模型好看」不是选型标准；要能映射到同一套 Humanoid 骨架与键盘标定（方案 5.2 中期） |
| **贴图 / 材质** | 每张贴图的来源与许可证、是否可商用、是否要求署名、分辨率与内存占用 | 模型自带贴图仍需**单独**登记 |
| **动画 / 动作数据** | 动作数据来源、许可证、采集者 / 演员授权、是否允许再训练、坐标尺度与骨骼命名 | 动捕数据往往有**独立的采集授权**，与代码许可证无关 |
| **骨架权重 / Rig** | 骨骼映射规范、手掌朝向、手腕轴、关节命名、坐标尺度、默认坐姿、权重是否允许再分发 | 「可重定向」不等于「可自由再分发权重文件」 |
| **音色采样** | 见第 3.3 节（五项指标 + 许可条件） | 采样来源（如 Freesound）逐文件核对，不得沿用许可不明样本 |
| **字体** | 字体文件来源、许可证、是否允许嵌入 / 再分发、字符集覆盖（中文） | 内置 `LegacyRuntime.ttf` 随 Unity；替换为外部字体时必须单独登记 |

### 3.3 音色采样必须同时评估的五项（方案 7.3 / 5.4）

若后续把 `PianoAudioSynth` 从波形合成替换为采样音色，除许可证外**必须评估**：

1. **延迟**（从 Note On 到发声的时间）——钢琴教学对时间同步敏感；
2. **长音衰减**——合成音为固定衰减，采样需覆盖长音符时长；
3. **力度响应**——多力度层采样或等效方案；
4. **同时发声数**——和弦 / 踏板共鸣时的声部数与内存；
5. **许可条件**——明确 CC0 / 公有领域或已授权，登记来源与署名要求。

并保留**波形合成作为降级模式**（方案 7.3：零采样依赖的优点应保留）。
